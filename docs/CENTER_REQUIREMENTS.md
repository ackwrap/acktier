# AckTier 中心端：开发需求与验收

本文定义中心端需求和验收。数据库路径、备份与停机重置密码见[部署说明](OWNER_CONTROL.md#中心存储与备份)。管理监听默认仅绑定回环，中心没有签名权限。

## 1. 目标与权限

中心 `acktier-server` 承担协调、申请管理、授权分发、STUN、中继，并承载正式管理页面。首次部署由管理员**明确选定一台客户端作为所有者（控制端）**，不是第一个注册的节点。所有者私钥只保存在控制端；控制端可以关机，授权有效期内不必在线。

| 角色 | 可以做什么 | 不能做什么 |
| --- | --- | --- |
| 中心 Web 管理员 | 密码登录；首次绑定公钥；查看节点和申请；发放或吊销申请码；导入、编辑和导出草稿；上传已签授权 | 代所有者签名、替换已绑定所有者、直接激活草稿或修改已签策略 |
| 控制端（所选所有者客户端） | 在本地核对并签发授权；如显式开启委托，凭自己的独立设备凭据调用管理 API | 把签名私钥放在中心；让中心远程触发本地签名 |
| 普通节点，包括已批准的节点 | 用申请码提交申请；用自身节点凭据注册、上报、获取 NetMap；本地验签后通信 | 登录管理页面、查询其他节点申请、管理申请码或调用管理 API |
| 中心服务本身 | 保存并校验公开信任材料，持久化并发布已签版本；维护不可信的连接提示 | 生成、接收或存储 `signer.json`，自行授予成员身份、换钥、修改 ACL、批准路由或延长签名有效期 |

Web 密码、控制端 API 凭据、申请码和节点令牌四者相互独立，不得互换。节点如何注册、它的 IP 和节点公钥是否在已签名单里，都不能成为管理权限依据。

## 2. 启动、网络隔离和登录

- **独立监听。** Web 管理台默认仅监听回环地址，建议 `127.0.0.1:8081`，入口 `/admin/`。节点控制与中继监听器与 Web 使用不同的路由和监听地址；默认在节点端口访问 `/admin/` 或管理 API 返回 `404`。不得为管理端口自动配置 UPnP、端口映射、反代或公网转发。
- **显式远程访问。** 默认可经 SSH 隧道从运维电脑访问回环管理台；直接远程管理必须显式配置监听地址并启用 HTTPS，宜只绑定管理网地址。节点端为了联调而允许明文，不得顺带开放远程明文管理。
- **独立管理员密码。** 首次由中心本机的部署流程设密码，或使用自动生成的私有初始凭据；没有固定默认密码。常规登录只用管理员密码且通过服务端校验；库内只保存带随机盐的 Argon2id 哈希。本机离线重置需要停止中心，重启后旧会话失效；在 Web 改密时其他会话立即失效。不得将密码放入 URL、日志或传给节点。
- **安全会话。** 角色检查在服务端。会话 ID 随机，支持退出和到期；Cookie 使用 `HttpOnly`、适用的 `SameSite`，并在 HTTPS 下置 `Secure`。状态变更要求 CSRF 与同源校验；登录和请求体大小限额；阻止被嵌入页面；敏感响应禁止缓存。失败登录限速，不回显提交的密码。
- **无所有者时仍可启动。** 已授权管理员能打开首次绑定页面，健康检查可报告待初始化；绑定前注册、心跳、NetMap 和中心中继都不可用。不得回退到无所有者的旧模式。

## 3. 首次绑定和控制端 API

1. 在选定客户端运行 `acktier owner init`。只通过可信渠道转交 `trust.json`；私钥文件 `signer.json` 留在选定客户端。所有者签名密钥不是节点 `NodeKey`。
2. 用 Web 密码登录，上传 `trust.json`，核对组网指纹与所有者公钥并确认来源。信任文件中的最低可接受授权版本随公钥一起持久化，界面不显示编号。中心持久化成功后才开放注册；无须重启。并发绑定只能有一份成功，写入失败保持待初始化。保留 `-owner-trust` 供非交互部署；不能借该参数或 Web 覆盖已固定的根。
3. 所有普通节点从可信渠道独立取得所有者公钥，不从未认证的中心页面自动采信。选定的控制端如果也上数据面，其 `NodeKey` 同样必须由所有者签入成员列表。
4. **管理 API 默认不对外提供。** 管理员可以显式启用委托，通过独立管理入口给选定控制端开放；不把整套管理路由加到普通节点监听。委托时绑定控制端管理公钥或客户端证书，验证它持有对应私钥。不接受 Web 密码、浏览器会话、普通节点的 `NodeToken`、申请码、公钥字符串或自报设备名作为 API 认证。
5. 控制端可读申请、成员、能力与有效授权，管理申请码、读写草稿并提交已签文件。可使用固定客户端公钥的 mTLS；若用签名请求，则将一次性短期挑战、组网／服务标识、HTTP 方法、目标和请求体摘要一并绑定，并防并发重放；API 身份证明与策略签名使用不同密钥或明确分域。取消委托后原凭据立即失效，不影响已签策略或节点已有权限。**API 不包括签名和替换所有者根。**

## 4. Web 页面与日常操作

| 页面 | 必须提供 |
| --- | --- |
| 登录与首次初始化 | 独立密码登录；绑定前只进入初始化向导；明确仅接收 `trust.json`，预览指纹、确认绑定；可区分未设置、已绑定和写入失败 |
| 概览 | 组网指纹、活动授权版本、到期状态、待签草稿数、待处理申请、已签成员、最近上报及中继状态；「已绑定」「已签」「在线」分别表示不同状态 |
| 入网申请 | 搜索和分页；显示名称、系统、节点公钥、最近上报、传输能力与申报网段；可将核对过的申请加入草稿，按钮不叫直接「批准入网」 |
| 节点详情 | 对照**已签身份**（名称、地址、标签、获批子网／出口）与**节点上报**（绑定端口、候选地址、申报路由、最近上报）。标明缺少数据、离线、已撤权和授权过期；支持上传能力清单用于核对 |
| ACL 与策略 | 查看当前已签规则；上传 ACL／完整策略 JSON；校验，逐条显示来源、目标、协议、目的端口及拒绝／放行；与当前版本对比并导出待签文件 |
| 签名发布 | 上传 `authorization.json`；显示签名结果、版本、到期时间和变更摘要；明确拒绝原因；浏览历史版本与审计记录。历史版本可查看，不提供降级按钮 |
| 申请码与安全 | 创建有期限的申请码，默认单次使用；生成时一次性显示明文；列表只显示备注、过期和使用状态，并可吊销；查看管理委托状态及关键操作记录 |

管理页有真实的列表、详情、上传校验、空状态和错误提示，不使用写死的数据。能用键盘完成表单操作，小屏幕表格不挤出页面；不依赖 JavaScript 才能执行基本管理操作的服务端页面是可选实现。审计至少记时间、操作者、动作、目标、结果与相关版本或摘要，不记密码、私钥、Cookie 或申请码明文。

### 4.1 协议、端口和节点能力

注册和后续认证心跳由节点自动上报能力，包括 `udp`、`tcp`、`quic`、`wss` 中实际启用的传输、本地监听端口、对外候选 IP:端口和申报路由。中心也提供**页面上传能力清单**入口：绑定到明确的节点公钥，预览后保存用于人工核对。页面应区分节点自动上报和人工导入，显示更新时间，在同一区域对照，不能悄悄把人工导入当作在线上报。老客户端无此字段时显示「未上报」，不从名称猜测。

| 概念 | 示例 | 如何使用 |
| --- | --- | --- |
| 传输监听端口 | QUIC `41000`、WSS `443` | 说明节点自己的传输监听能力，不代表其他节点能访问 |
| 候选地址 | `203.0.113.15:45000`／UDP | 提示实际可尝试连接的地址；NAT 映射端口可以与监听端口不同 |
| ACL 业务端口 | `node:2:8443`／TCP | 由签名策略规定的组网流量权限；**不**从传输端口自动推导 |

支持的协议、`1–65535` 端口、字面量 IP、IPv6 格式、地址和 CIDR 数量均须校验并限制。不得根据上传文件主动探测地址、开防火墙、批准路由或放行 ACL。人工导入的数据不进入节点 NetMap；可达连接提示继续走已有、经过限制的节点上报路径。普通节点只能更新自己的库存信息。

### 4.2 ACL 草稿、签发和生效

1. 管理员可上传单独的 ACL JSON，套用到已选的完整草稿；也可上传完整 `policy.json`，包括 `members`、`acl`、DNS、路由和可选 STUN 设置。草稿保存时记录基于哪个签名版本。只上传 ACL 不得隐式清空成员、DNS 或路由。两种上传都不是发布。
2. 验证 JSON 模式、规则动作、来源／目标选择器、协议、端口范围、组与主机别名、路由和成员冲突。拒绝以节点自报主机名作为信任选择器。预览可显示宽泛规则、引用不存在的节点、移除成员和默认拒绝带来的影响。TCP／UDP 的目的端口是业务端口；QUIC／WSS 是传输方式，不应被误当成可独立匹配的 ACL 层协议。
3. 页面可导出完整 `policy.json`。所有者在选定客户端通过节点本机或其他可信渠道核对公钥和策略变更，再用 `acktier owner sign` 本地签发完整快照。中心和页面不能通过 API、JS、插件等方式要求本地自动签名。
4. 管理员在 Web 或控制端通过已授予的 API 上传 `authorization.json`。中心对固定公钥验签，检查组网 ID、过期时间、版本与摘要；版本倒退、同版本内容不同、错误签名、过期或格式不合法均拒绝。相同有效快照重复提交可幂等成功。不在中心重新序列化签名载荷。
5. 事务提交后才分发快照。节点本地再验签并持久化版本，据此执行成员、ACL、DNS、路由及撤权。撤权不等于吊销申请码；前者要签发删除该成员的新版本。控制端离线时仍可以处理草稿、分发已签文件，但不能新签授权。

## 5. SQLite 持久化

**中心使用 SQLite 作为唯一持久化状态来源，首次运行直接建库。** 节点状态和所有者签名目录仍保存在各自设备。`-data=` 可用于临时内存存储。保留现有跨平台构建条件。

| 持久化对象 | 最低要求 |
| --- | --- |
| 首次绑定、管理密码、API 委托 | 单一所有者根与最低可接受版本、密码哈希、选定控制端的管理公钥／证书状态；不包含签名私钥 |
| 节点、申请、能力上报 | 稳定 ID、公钥与状态；节点令牌校验值；明确区分申请、签名成员、节点上报与人工导入 |
| 申请码 | 校验值、用途、有效期、使用次数、吊销标记；不得通过列表恢复明文 |
| 草稿与策略 | 版本化草稿、基准版本、校验状态；已签载荷原始字节、签名、摘要、版本、到期时间与当前指针 |
| 审计 | 按时间查询的关键操作记录 |

- 订好唯一约束及索引。首次绑定、申请码消费与新节点注册、签名版本推进、吊销与相关审计应各自原子提交；失败不得先改变内存态或已发布状态。心跳更新只写涉及的记录，而非每次重写全库。
- SQLite 文件和日志、WAL 或回滚日志、备份所在目录只对中心服务账号及授权运维人员可读写。选择适合单中心进程的锁与超时策略。不要把普通文件复制当作运行中的有效数据库备份；使用 SQLite 的一致性备份方式或停机备份。
- 无法读取已有库或提交写入时须报告，不得清空已有状态、取消所有者绑定或恢复旧授权。重启后重新验证活动快照和签名历史，不能倒退签名高水位。

## 6. 接口边界与验收

建议保留现有 `/api/v1/node/register`、`/api/v1/node/heartbeat`、`/api/v1/node/map/stream` 和 `/relay`。浏览器走 `/admin/` 下的会话路由；控制端走有独立认证的 `/api/v1/admin/`，两套入口可共享业务逻辑但不可共享凭据。旧的直接 `acl set`、`route approve`、`rekey` 等不能绕过所有者签名。请求／认证错误不要泄漏其他节点信息、上传内容或认证秘密。

| 验收项 | 通过条件 |
| --- | --- |
| 默认隔离 | 从非回环地址及节点端口访问不了 Web；节点端口不提供管理 API；未授权的远程明文请求不启用管理 |
| 密码 | 无密码、错密码、过期会话和跨站表单无法管理；正确密码可登录、退出；本地重置使旧会话失效；日志不泄密 |
| 首次安装 | 空库可启动，注册、心跳、流和中继均暂停；明确选择后正常；上传私钥、重复或竞态绑定被拒；重启不重新进入绑定 |
| 权限分离 | 开启委托后，选定控制端通过自己的凭据可用；普通成员、申请码、节点令牌、Web 密码及会话均失败；关闭委托后立即不可用 |
| 能力库存 | 注册的测试节点至少上报两种传输和端口，心跳能更新；页面可导入并显示人工清单，拒绝无效数据，不改变 ACL 或实际路由 |
| ACL 流程 | 从 Web 上传并预览真实规则，导出到离线控制端签发；未签草稿不改变流量，正确签名发布后节点按新规则收发；篡改、异网、过期和回滚均失败 |
| 持久化 | SQLite 重启后绑定、节点、草稿、签名与计数正确；故障注入不留下半条记录；并发使用同一个单次码只有一次成功；运行中的库拒绝离线密码重置 |
| 端到端 | 真实浏览器走完登录、绑定、能力导入、策略上传与发布；两个 memory TUN 节点能申请、验签入网和按策略通信，撤权后失去权限；所有者进程不常驻 |

项目根目录可执行 `go test -count=1 ./...`、`go test -race -count=1 ./...` 与 `go build ./cmd/...`。相关起点见 [所有者架构](OWNER_CONTROL.md) 与 [项目计划](PROJECT_PLAN.md)。

另可用 Node.js 22+ 和 Chrome/Chromium 运行浏览器回归：

```bash
go build -o bin/ ./cmd/...
node scripts/check-admin-browser.mjs bin /path/to/chrome
```
